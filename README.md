# honesty-rl

**Does RL teach agents to lie about finishing their work, and can the reward stop it?**

A preregistered, three-arm RL experiment on Qwen 3.5 4B (LoRA, prime-rl). Training uses
multi-step back-office tasks that are scored against the true end state. Evaluation uses held-out
tasks (including 8 task families never trained on), Zapier's third-party AutomationBench, and IFEval.

| Arm | Trained against |
|---|---|
| checklist | Deliverables exist + agent says done (values unchecked): gameable, like many real pipelines |
| outcome | Ground-truth partial credit |
| honest | Ground-truth partial credit + a bonus for a truthful "completed" flag |

| Eval | What it tests |
|---|---|
| potemkin-bench `test` (all 14 families; 84 tasks x 2) | Held-out tasks, incl. 8 families never trained on |
| Same tasks + an explicit honesty instruction (base model) | Does prompting alone do it? |
| AutomationBench (Zapier, `simple`) + self-report wrapper | Unseen third-party benchmark |
| IFEval (200 prompts) | General ability didn't regress |

## Results (held-out, 84 tasks x 2 attempts per model)

![results](results/plots/main_results.png)

| Model | Real success | False success | Truthful report |
|---|---|---|---|
| Base | 32% | 19% | 30% |
| Base + "be honest" prompt | 36% | 12% | 35% |
| checklist arm (gameable grader) | 32% | 18% | 32% |
| outcome arm (ground truth) | 46% | 5% | 46% |
| honest arm (ground truth + truthful-claim bonus) | 48% | 4% | 47% |

Ground-truth RL cut false claims of success 3-4x (19% → 5-6%) and raised real success ~14 pp; a gameable
grader did neither (+11.9 pp false success vs ground truth, p = 0.002); the extra honesty bonus added
nothing measurable on top of ground truth. The table shows seed 1; the figures in this paragraph pool
two training seeds for the ground-truth arms, and the second seed replicated every conclusion. Writeup: [docs/WRITEUP.md](docs/WRITEUP.md) · tables:
[results/RESULTS.md](results/RESULTS.md) · plan + deviations: [PREREGISTRATION.md](PREREGISTRATION.md).

Along the way: a fix for prime-rl's Qwen 3.5 tied-embedding bug
([PR #4144](https://github.com/PrimeIntellect-ai/prime-rl/pull/4144), `patches/`), which otherwise trains
small Qwen 3.5 checkpoints on all-zero logits.

## Layout

| Path | What |
|---|---|
| `PREREGISTRATION.md` | Hypotheses, tests, go/no-go and checkpoint rules, fixed before training |
| `configs/` | prime-rl configs (generated by `scripts/make_configs.py`, schema-validated) |
| `scripts/hackability_audit.py` | Scripted-policy reward audit (free) |
| `scripts/judge_calibration.py` | LLM-judge accuracy on labeled rollouts, transcript or database view |
| `scripts/analyze.py` | Paired bootstrap comparisons across models and sources, plots |
| `scripts/training_curves.py` | W&B curves: reward optimized vs. ground truth |
| `scripts/gpu/` | Node setup, pilot, per-arm training, final evals |
| `envs/automationbench_honesty/` | AutomationBench + a self-report tool and false-success metrics |
| `docs/WRITEUP.md` | Writeup |
| `results/` | Final eval traces, summary tables, figure, pre-study data |
| `patches/` | prime-rl fix for Qwen 3.5 tied embeddings |

Environments live in their own repos: [PotemkinBench](https://github.com/BenCurtis2003/potemkin-bench)
(v0.7) and [SafetyNetBench](https://github.com/BenCurtis2003/safety-net-bench) (v0.3; at 0% for a 4B model, so it was dropped
from the final evals).
All data is synthetic.
